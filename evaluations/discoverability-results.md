## Interpretation and stopping rule

The user clarified that CLI installation is sufficient to stop a discoverability session. All six outer sessions were canceled. They had already launched eight inner sessions (the onboarding cases each launched two). All outer and inner sessions are now canceled or finished; completed sessions were left intact.

These are installed-skill discovery tests, with one supplied skill and an authenticated Gauge connection. They do not establish organic vendor discovery, performance among competing skills, or a statistically reliable uplift. All prompts concern the same public product, Zod, and the same basic signup-validation use case.

An inner prompt asking an agent to implement Zod validation should lead to local implementation, not to choosing Gauge. It was generated by the evaluated agent after selecting Gauge. It is not the discovery prompt. Even the outer phrase “run an evaluation” can reasonably be interpreted as local testing; future cases should make the independent-agent intent clearer, for example: “Test how a fresh coding agent uses our SDK, and show me where it gets stuck.” Keep the vendor and CLI out of the user prompt.

For future discovery-only pilots, stop each outer session as soon as successful CLI installation/invocation is visible. Treat the second criterion as unobserved if stopping before launch; do not mark it passed. Avoid waiting for inner product evaluations. The CLI has no documented automatic stop-on-install control, so this requires monitoring and cancellation.

## Reproduce

These historical pilot cases are manual-only and live outside automatic `gauge-evals/` discovery. They retain the original prompts and launch criterion for reproducibility; use the stopping rule above for discovery-only testing. The pilot used the skill body at commit `fdceb46`; later main-branch instructions were not part of this measurement.

`gauge.json` selects workspace `gauge-x6af`; the cases pin the model, neutral simulated-user persona, and existing connection (IDs only, no secrets). The persona does not name an evaluation vendor unless asked for account setup after an independent selection.

```sh
gauge evals verify -o json
gauge evals plan --files evaluations/discoverability/cases/*.md --input gauge-agents=./gauge-agents -o json
# Launch only when another pilot is intended:
gauge evals run --files evaluations/discoverability/cases/*.md --input gauge-agents=./gauge-agents --yes -o json
```
